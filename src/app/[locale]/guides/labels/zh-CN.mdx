## 关于标签

atproto 中的审核由多个可堆叠系统组成，包括：

1. 网络删除，过滤 API 中的内容
2. 审核服务在内容上放置的标签
3.用户控制，例如静音和阻止

构建客户端应用程序的开发人员应该了解如何应用标签和用户控件。

**标签**是关于 AT 生态系统中任何帐户或内容的元数据形式。标签由“审核服务”发布，这些标签要么硬编码到应用程序中，要么由用户选择。它们附加到“labels”键下的响应中的记录。标签可以是有时间限制的。

## **标签值**

标签的*值*将决定其行为。一些示例标签值是“porn”、“gore”和“spam”。

标签值是字符串。目前它们只能是小写 a-z 或破折号字符“^[a-z-]+$”。其中一些以“！”开头，但只能由全局标签值使用。

标签值由其定义来解释。这些定义包括以下属性：

- “模糊”可能是“内容”或“媒体”或“无”
- “严重性”可以是“警报”或“通知”或“无”
- `defaultSetting` 可以是 `hide` 或 `warn` 或 `ignore`
- `adultOnly` 是布尔值

还有其他定义属性，但它们仅由全局标签值使用。

## **全局标签值**

有一些由协议定义的标签值。他们是：

- `!hide` 对无法点击的内容发出一般警告，并从列表中过滤内容。用户不可配置。
- `!warn` 在内容上放置一般警告，但可以点击。用户不可配置。
- `!no-unauthenticated`，这使得在尊重该标签的应用程序中注销的用户无法访问内容。
- “色情”，在图像上放置警告，只有当用户年满 18 岁并启用成人内容时才能点击。
- “性”，其行为类似于“色情”，但旨在处理不太强烈的性内容。
- “图形媒体”，其行为类似于“色情”，但用于暴力/血腥。
- “裸体”会对图像发出警告，但年龄未满 18 岁且默认忽略。
- “机器人”表示帐户是自动化的。

全局标签值存在的原因有两个。

第一个是因为只有全局定义的标签值才能用作自标签（即由不是贴标者的用户设置）。因此，色情、性、血腥、裸体和未经认证的标签是全球性的。

第二个是因为一些特殊行为，例如“不可配置”和“仅适用于注销用户”，无法应用于自定义标签。因此，!hide、!warn 和 !no-unauthenticated 标签是全局的。

## **自定义标签值**

贴标签者可以定义自己的标签值。每个贴标机都有自己定义的标签值的命名空间。自定义定义可以覆盖定义贴标机的所有全局定义，以“!”开头的定义除外，因为这些定义是保留的。

由于有两个行为属性（“模糊”和“严重性”），每个属性具有三个值，因此自定义标签值有 9 种可能的行为。

| **模糊** | **严重性** | **描述** |
| --- | --- | --- |
| `内容` | `警报` |隐藏内容并在查看内容时贴上“危险”警告标签 |
| `内容` | `通知` |隐藏内容并在内容上放置“中性”信息标签（如果查看）|
| `内容` | `无` |隐藏内容 |
| `媒体` | `警报` |隐藏内容中的图像，并在查看时在内容上贴上“危险”警告标签 |
| `媒体` | `通知` |隐藏内容中的图像，并在查看内容时在内容上放置“中性”信息标签 |
| `媒体` | `无` |隐藏内容中的图像 |
| `无` | `警报` |在内容上贴上“危险”警告标签 |
| `无` | `通知` |在内容上贴上“中立”信息标签 |
| `无` | `无` |无视觉效果|

可能用于标签的一些定义示例

- 骚扰：“模糊=内容”+“严重性=警报”
- 蜘蛛警告：`blurs=media` + `severity=alert`
- 错误信息：“模糊=无”+“严重性=警报”
- 已验证用户：`blurs=none` + `severity=inform`
- 策划下调：`blurs=none` + `severity=none`

“defaultSetting”确定当用户首次订阅贴标机时如何配置标签。

`adultOnly` 确定如果禁用成人内容，标签是否应该可配置。

## **标签配置**

用户可以选择隐藏、警告或忽略贴标机的每个标签。隐藏和警告基本上类似，只不过隐藏也会从提要和列表中过滤带标签的内容。忽略只是忽略标签。如果首选项中未启用成人内容，则该行为应强制隐藏而不覆盖。

有关更多信息，请参阅[标签](/specs/label) 规范。
