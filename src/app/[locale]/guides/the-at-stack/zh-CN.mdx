## 认证传输协议

AT 协议（身份验证传输协议）是公共对话的标准，也是构建社交应用程序的开源框架。

它为社交应用程序上的用户身份、关注和数据创建了标准格式，允许应用程序进行互操作，并允许用户在它们之间自由移动。它是一个具有帐户可移植性的联合网络。

## 去中心化架构

AT 在联合网络模型中同步存储库。联合确保网络使用方便且可靠可用。存储库数据通过标准 Web 技术（HTTP 和 WebSockets）在服务器之间同步。

[**个人数据服务器** ，或 PDS](/guides/the-at-stack#pds)，是你在云中的家。他们托管你的数据、分发数据、管理你的身份，并协调对其他服务的请求以向你提供视图。

**中继** 处理你的所有事件，例如检索大规模指标（点赞、转发、关注者）、内容发现（算法）和用户搜索。

AT 协议以“大世界与小世界后备”的方式构建，以开放网络本身为模型。通过网络，各个计算机将内容上传到网络，然后所有这些内容都被广播回其他计算机。同样，通过 AT 协议，我们将消息发送到数量少得多的大型聚合器，然后这些聚合器将数据广播到网络上的个人数据服务器。

从技术上讲，你可以仅使用单个 PDS 来实现 AT 应用程序 — 继电器不是规范的必要部分。它们使生态系统能够扩展到大世界的社交网络。

## PDS

PDS 实例为用户托管帐户，这需要类似于任何网络服务器的帐户管理和生命周期控制。虽然 AT 身份（DID 和句柄）理论上可以与 PDS 完全分离，但实际上 PDS 有望帮助管理用户的身份。

你可以[托管你自己的 PDS](/guides/self-hosting)。

用户数据存储在签名数据存储库中并由 DID 进行验证。签名数据存储库类似于 Git 存储库，但用于数据库记录，而 DID 本质上是用户证书的注册表，在某些方面类似于 TLS 证书系统。它们应安全、可靠且独立于用户的 PDS。

  <Image src={did} alt="" className="w-full max-w-md mx-auto" />

PDS 处理：

- 账户生命周期：注册、删除、迁移
- 帐户安全：电子邮件验证、密码重置流程、更改电子邮件流程
- AT 身份解析：DID、句柄。 [阅读更多](https://fusectore.dev/2025/01/04/atproto-identity.html)了解如何进行身份解析。
- 偏好和私有状态的存储
- 能够删除或暂停帐户，并处理审核联系人
- 密钥管理：AT签名密钥和PLC轮换密钥
- [PLC](https://web.plc.directory/) 身份操作和端点：更改句柄；验证、签署和提交 PLC 操作
- 电子邮件传送：用于重置流程以及转发审核邮件
- 使用存储库事件流进行数据同步
- 在存储库事件流上输出`#identity`和`#account`（即将推出）事件
- 通常能够管理默认句柄命名空间（基域）
- OAuth 客户端流程，包括 Web 登录页面和可选的 MFA

你可以将个人帐户的数据存储库从一个 PDS 自由迁移到另一个 PDS。这涉及将存储库导入和导出为 CAR 文件。有一些社区工具可以使这变得更容易：

- https://atproto.at/，它允许你浏览存储在你自己的存储库中的所有数据（以及当前托管在哪个 PDS 上）
- https://pdsmoover.com/，PDS 迁移工具集合
- https://boat.kelinci.net/，一组用于存储库导入和导出的接口
- https://github.com/bluesky-social/goat，我们的 Go AT 命令行工具。

PDS 实现许多 AT 端点，默认情况下会将请求代理到其他服务。缓存、CDN 等通常在 [App View](#app-views) 层实现。 AT 堆栈的大多数其他组件都设计为直接从 PDS“远离”加载，因此托管用户数据仍然经济实惠。

## 继电器

**中继** 实时处理你的所有事件。中继还处理各个 PDS 的速率限制和网络滥用，以确保整个网络的可用性。重要的是，中继本身并不解释存储库中的记录。他们只是暂时存储它们并将其转发给消费者。中继生成事件的 [**firehose** ](/guides/streaming-data)，它结合了来自多个存储库和 PDS 的 [事件流](/specs/event-stream)。

继电器可以在不同的规模下运行。全网络中继跟踪整个网络上的所有存储库，提供完整的覆盖范围。部分网络中继可能专注于特定社区、应用程序或区域，从而减少资源需求。专用继电器可以服务于特定的用例，例如学术研究、品牌监控或档案保存。

完整的网络中继的运行成本并不是特别昂贵，并且不需要专门的硬件，尽管它确实需要大量的入口和出口网络带宽，这是运行中继的主要成本。

有多个可用的中继，每个中继可能有自己的速率限制和网络策略。一些可用的继电器是：
- 来自 [microcosm](https://www.microcosm.blue/) 的 `relay.fire.hose.cam` 和 `relay3.fr.hose.cam`。
- 来自 [Blacksky](https://blackskyweb.xyz/) 的 `atproto.africa`
- 来自 [Upcloud](https://upcloud.com/) 的 `relay.upcloud.world`
- 来自 [Bluesky PBC](https://docs.bsky.app/docs/advanced-guides/firehose) 的两个。
- 来自 [firehose.network](https://firehose.network) 的三个

由 [Bluesky PBC](https://docs.bsky.app/docs/advanced-guides/firehose) 操作的中继可能是最常用的，因为这是许多 PDS 主机使用的参考 PDS 服务器实现的默认中继。他们在其网站上记录了他们的[速率限制](https://docs.bsky.app/docs/advanced-guides/rate-limits)。

## 轻敲

Tap 用于从 PDS 存储库同步 AT 网络的现有记录，然后通过中继继续从 firehose 接收新记录。

Tap 通过处理消防连接、验证、回填和过滤来简化 AT 同步。你的应用程序连接到 Tap 并仅接收你关心的存储库和集合的简单 JSON 事件，无需担心用于验证加密签名的二进制格式。水龙头特点：

- 验证存储库结构、MST 完整性和身份签名
- 自动回填：添加新存储库时从 PDS 获取完整的存储库历史记录
- 过滤输出：按 DID 列表、按集合或全网络模式
- 订购保证：现场活动等待历史回填完成
- 交付模式：带有 ack、即发即弃或 webhook 的 WebSocket
- 单个 Go 二进制文件
- SQLite 或 Postgres 后端
- 专为中等规模（数百万个存储库，30k+ 事件/秒）而设计

[@atproto/tap](https://www.npmjs.com/package/@atproto/tap) 有一个用于使用 Tap 的 TypeScript 库。

## 应用程序视图

**应用程序视图** 处理应用程序特定的逻辑，例如检索大规模指标（点赞、转发、关注者）、内容发现（算法）和用户搜索。

应用程序视图是实际组装你的提要和你在应用程序中看到的所有其他数据的部分，并且位于中继数据流的下游。这是一种语义感知服务，可在网络上生成聚合并在网络的某些子集上生成视图。例如，Relay 可能会抓取数据，例如某个帖子的点赞和转发，并且应用程序视图将输出这些指标的计数。

网络上部署的每个词典都可以有一个应用程序视图生态系统。例如，*Bluesky* 目前支持微博模式：`app.bsky` Lexicon。创建新词典的开发人员可以部署相应的应用程序视图来理解其词典来为用户提供服务。其他词典可能包括[视频](https://stream.place/)、[长篇博客](https://leaflet.pub/) 或[协作编码](https://tangled.org/)。通过引导现有的中继，这些新应用程序的数据整理已经得到处理。他们可以从已经在 Bluesky 上发帖并用其他词典填充他们的存储库的大量用户中受益；他们只需要提供其应用程序所需的索引行为。

应用程序视图是应用程序级工具，而不是 AT 协议的固有部分。应用程序视图通过 HTTP 响应 [XRPC](/specs/xrpc) 调用。

你可以在 [The Blacksky Architecture](https://blackskyweb.xyz/overview/#blacksky-architecture) 中找到其他 App View 实现的详细文档示例。不同的Atmosphere应用程序可能会做出不同的实现选择。

## DID PLC

默认情况下，新的 atproto 身份是使用 `did:plc` 文档创建的。

[did:plc](https://web.plc.directory/) 是一个自我验证的[去中心化标识符](https://en.wikipedia.org/wiki/Decentralized_identifier)，它具有强一致性、可恢复性，并允许密钥轮换。每个身份都由一系列签名操作组成，每个操作都引用链中的前一个操作回到创世操作。任何观察者都可以验证操作链，以验证身份的当前状态。

PLC 操作存储在一个目录中（当前在 [plc.directory](http://plc.directory) 上运行），该目录是一个集中式服务，用于验证操作、存储操作并为这些操作以及从操作派生的身份的计算视图提供服务。目录的信任模型相当有限，因为如果没有代表身份的签名操作，它就无法修改身份。

有关 PLC 镜像的指南，请参阅[此开发人员博客](https://dholms.leaflet.pub/3m6zswymcqk2p)。

## 提要

与网络搜索引擎一样，用户可以自由选择他们的聚合器。提要、搜索索引和整个应用程序视图可由独立第三方提供，PDS 根据用户配置路由请求。

<Container>
  <Image src={feeds} alt="" className="w-full max-w-md mx-auto" />
</Container>

自定义提要或提要生成器是通过 AT 协议向用户提供自定义算法的服务。这允许用户选择自己的时间线，无论是算法“为你”页面还是完全猫照片的提要。

自定义提要的工作方式非常简单：服务器接收来自用户服务器的请求，并返回带有一些可选元数据的帖子 URI 列表。然后，请求服务器将这些帖子合并为完整视图并发送回客户端。

Feed 生成器服务可以托管一种或多种算法。服务本身由 DID 标识，而它托管的每个算法则由创建它的帐户的存储库中的记录声明。例如，Bluesky 提供的提要可能会在“@bsky.app”的存储库中声明。因此，给定的算法由声明记录的 at-uri 来标识。该声明记录包括指向服务 DID 的指针以及提要的一些配置文件信息。

[浏览](https://blueskydirectory.com/feeds/all) 自定义提要。

## 鱼鹰和臭氧

审核由我们堆栈的两个部分处理：[*Osprey*](https://github.com/roostorg/osprey)，一个事件流决策引擎和分析 UI，旨在调查和采取自动操作；和 [*Ozone*](/guides/using-ozone)，一种用于做出审核决策的标签服务和网络前端。

## 工具和 SDK

大多数 AT 工具都是用 Go 和 TypeScript 实现的。

- [indigo](https://github.com/bluesky-social/indigo) 存储库包含我们的大部分 Go 工具，包括 [Relay](https://github.com/bluesky-social/indigo/blob/main/cmd/relay/README.md) 和 Go SDK 的代码。
- 还有 https://github.com/bluesky-social/goat，我们的 Go AT 命令行工具。
- https://github.com/bluesky-social/atproto 存储库包含我们的大部分 TypeScript 工具，包括 [PDS](https://github.com/bluesky-social/atproto/tree/main/packages/pds) 和 TypeScript SDK 的代码。 [atcute](https://github.com/mary-ext/atcute) 社区项目提供了替代的 TypeScript 包。
- 我们每天都使用许多其他社区工具。例如，用 Rust 编写的 [Microcosm](https://www.microcosm.blue/) 工具提供了一组 API 来帮助构建查询层，而无需专用的 AppView！详情请参阅 https://constellation.microcosm.blue/。
