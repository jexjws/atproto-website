<Note>
OAuth 环回的工作原理是使用特殊的重定向 URI（例如“http://127.0.0.1:PORT/callback”）将授权代码直接发送回应用程序，该应用程序侦听本地端口，避免基于浏览器的回调并为令牌交换启用安全、直接的通信。应用程序打开一个本地侦听器，而不是 Web 重定向，您可以在浏览器中进行身份验证，服务器重定向回应用程序的本地 URI，让应用程序获取代码并将其交换为令牌。它对于开发场景特别有用。
</Note>

流程如下：

1. `StartAuthFlow` 解析用户的句柄，发现其 PDS，发送 [推送授权请求 (PAR)](/guides/permission-sets#requesting-permissions)，并返回授权 URL。

＃＃ 结论

您已经在 Go 中构建了一个最小的 OAuth CLI 工具，可以使用 AT 协议进行身份验证。完整源代码大约有 120 行代码。

需要记住以下几点：

- **这适用于本地开发。** 本地主机客户端无法在生产环境中工作。有关具有 SQLite 持久性和多个命令的生产就绪型 Go 示例，请参阅 Cookbook 中的 [go-oauth-cli-app](https://github.com/bluesky-social/cookbook/tree/main/go-oauth-cli-app)。
- **会话位于内存中。** 每次运行都需要重新授权。 Cookbook 示例展示了如何使用 SQLite 保留会话。
- **范围。** 本教程仅请求基本“atproto”范围。要代表用户读取或写入数据，您需要额外的[范围](/guides/permission-sets)。

您可以在我们的 [Docs](/guides) 中找到更多指南和教程，并在 [Cookbook](https://github.com/bluesky-social/cookbook/) 存储库中找到更多示例应用程序。快乐建设！
