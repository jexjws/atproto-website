在本教程中，你将把上一教程中的 Statusphere 应用连接到运行 [Ozone](https://github.com/bluesky-social/ozone) 的标签服务。用户将在摘要中看到审核者发布的标签以及状态，并且能够向贴标签者报告状态以供审核。

## 先决条件

本教程以已完成的[创建社交应用程序](/guides/statusphere-tutorial) 教程为基础。在开始之前你应该先运行它。

你还需要一个可以管理的正在运行的 Ozone 实例。按照 [Ozone HOSTING 指南](https://github.com/bluesky-social/ozone/blob/main/HOSTING.md) 进行操作。在该设置结束时，你应该拥有：

- **贴标机 DID** （`did:web:...` 或 `did:plc:...`），其 DID 文档中包含 `#atproto_labeler` 和 `#atproto_label` 条目。当你[将帐户配置为贴标机](/guides/using-ozone#configuring-ozone) 时，会发生这种情况。
- 响应“GET /xrpc/com.atproto.label.queryLabels?uriPatterns=*”的 **公共服务 URL** 。 Ozone 实现了这个端点。
- Ozone UI 的**管理员登录**

确认贴标机是否可达的快速方法：

````bash
curl“https://<your-ozone-host>/xrpc/com.atproto.label.queryLabels?uriPatterns=*&limit=1”
````

在新安装的 Ozone 上，这应该返回 `{"labels":[]}`。

有几点值得指出：

- 端点 URL 来自贴标签者的 DID 文档。 DID 是信任锚 - 它的文档经过签名并告诉你“#atproto_labeler”服务实际位于何处。 Tap 缓存底层 DID 分辨率。
- lex `Client` 是根据解析的 URL 构建的，并且未经身份验证即可使用 — `queryLabels` 是公共端点。
- 每个标签的“src”是发布它的贴标者的 DID。这些被解析为句柄（每次调用都会进行重复数据删除）并作为“srcHandle”附加到每个“Label”，因此 UI 可以显示标记为状态的*who*，而不仅仅是不透明的 DID。

三个助手（“isHidden”、“isWarned”、“displayLabels”）解释这些值。 `!hide` 和 `!warn` 是具有规定 UI 行为的系统级标签；其他任何内容都是描述性标签，例如“垃圾邮件”或“笑话”，你可以根据需要呈现它们。

## 结论

你现在拥有一个 atproto 应用程序，它使用来自贴标机服务的签名标签并允许用户向其提交报告。对每个渲染进行查询适用于小型应用程序，但生产型消费应使用“com.atproto.label.subscribeLabels”处的 WebSocket 流来保持本地缓存最新 - 这是这里的下一步。

此设置也不假设任何 Bluesky 特定的内容：相同的 Ozone 实例、相同的协议端点和相同的客户端模式适用于任何需要社区审核的 atproto 应用程序。
