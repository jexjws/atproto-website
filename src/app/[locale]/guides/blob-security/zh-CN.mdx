## HTTP 请求

从网络服务器提供任意用户上传的文件会引发许多内容安全问题。例如，脚本或 SVG 内容的跨站点脚本攻击 (XSS) 与其他网页形成相同的“来源”。实际上，必须为 **`getBlob`** 端点启用[内容安全策略](https://developer.mozilla.org/en-US/docs/Web/HTTP/CSP)；实际上不支持直接从 Blob 存储（**`getBlob`** 端点）直接向浏览器和 Web 应用程序动态提供资源。应用程序在向浏览器和 Web 代理提供服务之前，必须通过独立的 CDN、代理或其他 Web 服务来代理 blob、文件和资产，并且此类服务应实施安全预防措施。

## 元数据

某些媒体类型可能包含敏感元数据。例如，JPEG 图像文件中的 EXIF 元数据可能包含 GPS 坐标。服务器可能会采取措施来防止此类元数据的意外泄漏，例如在保留 blob 之前删除此元数据。

媒体文件的解析是内存安全错误和安全漏洞的一个臭名昭著的来源。甚至内容类型检测（或“嗅探”）也可能成为漏洞的来源。强烈建议服务器不要在不使用强大的沙箱机制的情况下直接解析媒体文件（图像、视频、音频或任何其他重要格式）。特别是，PDS 实例本身不应该直接实现媒体大小调整或转码——这应该在应用层处理。

## 对抗性使用

更丰富的媒体类型增加了滥用和非法内容的风险。服务部门应实施适当的机制，在检测到和报告此类内容时将其删除。

服务器可能需要采取措施防止恶意资源消耗。例如，故意耗尽磁盘空间、网络拥塞、带宽利用率等——建议采用速率限制、大小限制和配额。
