<Note>
OAuth loopback works by using a special redirect URI (like `http://127.0.0.1:PORT/callback`) to send authorization codes directly back to an app, which listens on a local port, avoiding browser-based callbacks and enabling secure, direct communication for token exchange. Instead of a web redirect, the app opens a local listener, you can auth in a browser, and the server redirects back to the app's local URI, letting the app grab the code and exchange it for a token. It's particularly useful for development scenarios.
</Note>

`stateStore` 和 `sessionStore` 是内存中的映射。状态存储在 OAuth 握手期间保存临时数据；会话存储保存由 DID 加密的经过身份验证的会话。在生产应用程序中，你将使用数据库来实现这些。

## 第 3 部分：登录流程

现在添加登录流程。你将启动一个临时 HTTP 服务器来接收 OAuth 回调，然后打开用户的浏览器来授权应用程序：

<S05 />

流程如下：

1. `oauthClient.authorize(handle)` 解析用户的句柄，发现他们的 PDS，并返回授权 URL。
2.“open”包在用户的浏览器中打开该 URL，他们将在其中看到同意屏幕。
3. 用户批准后，他们的 PDS 会重定向回带有授权码的“http://127.0.0.1:3000/callback”。
4. `oauthClient.callback(params)` 交换该代码以获得经过身份验证的会话。

## 结论

你已经构建了一个最小的 OAuth CLI 工具，可以使用 AT 协议进行身份验证。完整源代码大约有 80 行代码。

需要记住以下几点：

- **这适用于本地开发。** 环回客户端无法在生产中工作 - 请参阅 [OAuth with NextJS 教程](/guides/oauth-tutorial) 以部署真实的应用程序。
- **会话位于内存中。** 每次运行都需要重新授权。对于持久会话，请使用[NextJS 教程](/guides/oauth-tutorial#part-3-adding-database-persistence) 中所示的数据库。
- **范围。** 本教程仅请求基本“atproto”范围。要代表用户读取或写入数据，你需要额外的[范围](/guides/permission-sets)。

你可以在我们的 [Docs](/guides) 中找到更多指南和教程，并在 [Cookbook](https://github.com/bluesky-social/cookbook/) 存储库中找到更多示例应用程序。快乐建设！
