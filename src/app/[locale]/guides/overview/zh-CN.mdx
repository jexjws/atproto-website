# 协议概述

**认证传输协议**，又名**atproto**，是一种用于大规模社交网络应用程序的去中心化协议。本文档将向你介绍 AT 协议背后的想法。

＃＃ 身份

AT Protocol 中的用户的账户拥有永久的去中心化标识符（DID）。它们还有一个可配置的域名，充当人类可读的句柄。身份包括对用户当前托管提供商和加密密钥的引用。

## 数据存储库

用户数据在[签名数据存储库](/guides/data-repos) 中交换。这些存储库是记录的集合，其中包括帖子、评论、点赞、关注等。

## 网络架构

AT 协议具有联合网络架构，这意味着帐户数据存储在主机服务器上，而不是终端设备之间的点对点模型。选择联合是为了确保网络易于使用且可靠可用。存储库数据通过标准 Web 技术（[HTTP](/specs/xrpc) 和 [WebSockets](/specs/event-stream)）在服务器之间同步。

我们网络中的三个核心服务是个人数据服务器 (PDS)、中继和应用程序视图。还有饲料发生器和贴标机等配套服务。

可以以不同方式堆叠在一起的较低级别原语是存储库、词典和 DID。我们[在我们的博客上]发布了有关联邦架构的技术决策概述(https://bsky.social/about/blog/5-5-2023-federation-architecture)。

## 互操作

名为 [Lexicon](/specs/lexicon) 的全局模式网络用于统一跨服务器调用的名称和行为。服务器实现“词典”来支持功能集，包括用于同步用户存储库的核心“com.atproto.*”词典和提供基本社交行为的“app.bsky.*”词典。

当网络交换文档时，AT 协议交换原理图和语义信息，使不同组织的软件能够理解彼此的数据。这使 atproto 客户端可以自由地独立于服务器生成用户界面，并且无需在浏览内容时交换渲染代码 (HTML/JS/CSS)。

## 实现规模化

个人数据服务器是你在云中的家。他们托管你的数据、分发数据、管理你的身份，并协调对其他服务的请求以向你提供视图。

中继将来自多个服务器的数据更新收集到单个消防管道中。

应用程序视图提供整个网络的聚合应用程序数据。它们支持大规模指标（点赞、转发、关注者）、内容发现（算法）和用户搜索。

这种角色分离旨在为用户提供多个可互操作提供商之间的选择，同时还可以扩展到大型网络规模。

## 算法选择

与网络搜索引擎一样，用户可以自由选择他们的聚合器。源、标签器和搜索索引可以由独立第三方提供，并由 PDS 根据客户端应用程序配置路由请求。客户端应用程序可能与特定服务相关联，例如应用程序视图或强制标签。

## 账户可移植性

我们假设个人数据服务器可能随时发生故障，要么完全离线，要么停止为特定用户提供服务。 AT 协议的目标是确保用户可以将其帐户迁移到新的 PDS，而无需服务器的参与。

用户数据存储在[签名数据存储库](/guides/data-repos)中，并通过[DID](/guides/identity)进行身份验证。签名数据存储库类似于 Git 存储库，但用于数据库记录，并且 DID 提供加密密钥目录，在某些方面类似于 TLS 证书系统。身份应安全、可靠且独立于用户的 PDS。

大多数 DID 文档都会发布两种类型的公钥：签名密钥和轮换密钥。

* **签名密钥**：验证用户的数据存储库。所有 DID 都包含这样的密钥。
* **旋转键**：断言对 DID 文档本身的更改。 PLC DID 方法包含此内容，而 DID Web 方法则不包含此内容。

签名密钥委托给 PDS，以便它可以管理用户的数据，但轮换密钥可以由用户控制，例如作为纸钥匙。这使得用户无需原始主机的帮助即可将其帐户更新到新的 PDS。

用户数据的备份可以作为备份永久同步到用户自己的设备（取决于可用的磁盘空间），或者由第三方服务进行镜像。如果他们的 PDS 在没有通知的情况下消失，用户应该能够通过更新他们的 DID 文档并上传他们的数据备份来迁移到新的提供商。

## 言论、影响力和节制

AT 协议的模型是 _speech_ 和 _reach_ 应该是两个独立的层，旨在相互协作。 “言论”层应该保持宽松，分配权力，并旨在确保每个人都有发言权。 “到达”层位于顶部，专为灵活性而设计并可扩展。

atproto 的基础层（个人数据存储库和联合网络）创建了一个公共的言论空间，每个人都可以自由参与，类似于任何人都可以建立网站的 Web。然后，索引服务通过聚合来自网络的内容来实现覆盖，类似于搜索引擎。
