## 关于适度

atproto 模型是 *speech* 和 *reach* 应该是两个独立的层，旨在相互协作。 “言论”层应该保持宽松，分配权力，并旨在确保每个人都有发言权。 “到达”层位于顶部，专为灵活性而设计并可扩展。 Atproto 审核是使用[标签](/guides/labels) 实现的。

我们的审核架构由两项服务提供：[*Osprey*](#algorithmic-moderation)，一个事件流决策引擎和分析 UI，旨在调查和采取自动操作；和 [*Ozone*](/guides/using-ozone)，一种用于做出审核决策的标签服务和网络前端。

[阅读更多](https://docs.bsky.app/blog/blueskys-moderation-architecture) 关于我们博客上的审核。

## 算法审核

[Osprey](https://github.com/bluesky-social/osprey-atproto) 是一个事件流决策引擎和分析 UI，旨在调查并采取自动操作，以实现可持续的大规模审核。它使用[Kafka](https://kafka.apache.org/)及其自己的[规则引擎](https://github.com/roostorg/osprey/blob/main/docs/rules.md)。

从另一个角度来看，Osprey 是一个 Python 库，用于通过人类编写的规则处理操作，并将标签、Webhooks 输出回 API 和其他接收器。它使用结构化逻辑、用户定义的函数和外部信号来评估事件，以分配标签、结论和操作。它可以利用经过微调的 LLM 和其他分类器，将自己的 Web 端点公开给 Osprey。法学硕士可以成为展示审核报告的有用工具；这些报告可以根据你的配置自动和/或手动执行。

Osprey 由 [Roost](https://roost.tools/) 维护，他们构建了开源审核工具。
