# 密码学

AT 协议使用公钥加密技术来验证公共数据。为了简单性和一致性，通过协议框架重用了少量的密码系统和签名技术。尽管许多组件使用基于 TLS 的安全网络传输，但数据加密并未直接在协议中使用。 {{ className: '领导' }}

目前支持两条椭圆曲线，预计实现将完全支持这两种曲线：

- `p256` 椭圆曲线：又名“NIST P-256”，又名“secp256r1”（注意“r”），又名“prime256v1”
    - 该曲线*包含在 WebCrypto API 中。它通常由个人设备硬件（受信任的平台模块 (TPM) 和移动安全区域）和云硬件安全模块 (HSM) 支持
- `k256` 椭圆曲线：又名 `secp256k1` （注意 `k`）
    - 该曲线*不*包含在 WebCrypto API 中。由于它在包括比特币在内的流行加密货币中使用，它受到个人密钥管理技术和硬件的广泛支持。云 HSM 也支持它。

由于写出完整曲线名称时存在细微的视觉区别，因此它们通常被称为“p256”或“k256”。

原始的 atproto 参考实现始终支持这两种曲线类型。生成新密钥对时，默认使用“k256”。

两个系统的关键点都具有无损“压缩”表示，这在共享公钥时非常有用。这通常是“k256”本身支持的，但有时需要额外的方法或为“p256”跳过障碍。你可以在以下位置阅读更多相关信息：[02、03 或 04？那么什么是压缩和未压缩的公钥？](https://medium.com/asecuritysite-when-bob-met-alice/02-03-or-04-so-what-are-compressed-and-uncompressed-public-keys-6abcb57efeb6)。

在 atproto 中签署数据时的常见模式是：

- 以严格的 CBOR 格式对数据进行编码 ([DRISL](https://dasl.ing/drisl.html))
- 使用 SHA-256 对生成的 CBOR 字节进行哈希处理，生成原始字节（不是十六进制编码的字符串）
- 对哈希字节进行签名。

## ECDSA 签名延展性

某些 ECDSA 签名可以转换为生成新的不同但仍然有效的签名。这不需要访问私有签名密钥或已签名的数据。使用此属性可能进行的攻击范围是有限的，但它是一个意外的属性。

具体来说，对于“k256”，区别在于“低 S”和“高 S”签名之间的区别，如 [Bitcoin BIP-0062](https://github.com/bitcoin/bips/blob/master/bip-0062.mediawiki) 中所述。

在 atproto 中，“p256”和“k256”曲线都需要使用“low-S”签名变体。

在 atproto 中，应始终使用加密库提供的验证例程来验证签名，而不是通过将签名值与原始字节进行比较。

## 公钥编码

将公钥编码为字符串时，首选表示形式是 `did:key` 使用的“多密钥”编码。因为该表示包括指示曲线类型的“编解码器”，所以可以模糊地解析它们。

以这种格式编码公钥的过程是：

- 将公钥曲线“点”编码为字节。请务必使用较小的“紧凑”或“压缩”表示形式。这对于“k256”通常很容易，但可能需要“p256”键的特殊参数或配置
- 在关键字节前面添加适当的曲线编解码器值，作为变体编码字节：
    - `p256`（压缩，33 字节密钥长度）：`p256-pub`，代码 0x1200，varint 编码字节：[0x80，0x24]
    - `k256`（压缩，33 字节密钥长度）：`secp256k1-pub`，代码 0xE7，varint 字节：[0xE7，0x01]
- 使用“base58btc”对组合字节进行编码，并使用“z”字符作为前缀，生成字符串

解码过程反向相同，使用识别的曲线类型作为上下文。

要将密钥编码为“did:key”标识符，请使用上述多密钥编码，并添加 ASCII 前缀“did:key:”。该标识符用作 DID PLC 方法中的内部实现细节。

请注意，[atproto DID 规范文档](/specs/did) 中描述了一种变体传统“multibase”编码，它不包括编解码器类型值，并使用密钥的未压缩字节编码。这种格式已被弃用。

### 编码示例

一个 P-256 公钥，编码为多密钥和 `did:key`：

````
zDnaembgSGUhZULN2Caob4HLJPaxBh92N7rtH21TERzqf8HQo
做了：关键：zDnaembgSGUhZULN2Caob4HLJPaxBh92N7rtH21TErzqf8HQo
````

一个 K-256 公钥，编码为多密钥和 `did:key`：

````
zQ3shqwJEJyMBsBXCWyCBpUBMqxcon9oHB7mCvx4sSpMdLJwc
做了：关键：zQ3shqwJEJyMBsBXCWyCBpUBMqxcon9oHB7mCvx4sSpMdLJwc
````

## 使用和实施指南

atproto 生态系统中的私钥没有具体推荐的字节或字符串编码。有时使用简单的十六进制编码，有时使用多键编码，有时使用 JWK。

## 未来可能的变化

支持的加密系统集预计将缓慢发展。在任何时间点拥有尽可能少的系统都具有显着的互操作性和实施优势。
